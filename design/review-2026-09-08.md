Bewley code and capabilities review — 2026-09-08

Bewley has a useful and unusually broad foundation for agent-assisted qualitative research. Its strongest features are exact-span evidence, explicit review decisions, evolving codebooks, local storage, and an external model-execution boundary. The next release should strengthen provenance and recovery before broadening the data model. Several reproducible failures affect the guarantees on which downstream analysis depends.

Reviewed local and GitHub main commit `aaeec47196e48e830220801ececf541069e0cc8d`, package version 0.4.0. Read all seven open issues and their discussion; there were no open pull requests. Reviewed core persistence, annotation, query, export, bundle, workflow, and model-package paths alongside their tests.

**Validation performed.** `python -m compileall -q src` passed. The complete test suite passed twice: 247 tests in the existing environment, and 247 after `pip install -e .` into a temporary virtual environment using system site packages and a fresh EDSL checkout. Both runs reported two EDSL/Pydantic deprecation warnings. This was not a clean, dependency-isolated installation test. Repository `bewley fsck` passed. Targeted reproductions below used synthetic temporary projects and locally constructed Results; no inference or transcription was executed. Corruption checks modified only disposable fixture copies. No existing research material or project events were changed.

**Priority findings.** P1 means address before relying on the affected integrity or provenance guarantee; P2 means a material correctness or workflow gap.

1. **P1 — A failed undo can make the event log unrebuildable.** In `src/bewley/project.py:526`, `append_event` writes the event and advances HEAD before applying it to SQLite. Undo does not prevalidate name conflicts (`project.py:2584`). Reproduction through ordinary CLI commands: create `alpha`; rename it to `beta`; create another `alpha`; undo the rename. Undo exits with an SQLite uniqueness error, but its event remains appended. `rebuild-index` then fails on the same event. Validate domain constraints under the writer lock before accepting an event, and define recovery for interruptions between log and projection updates. Rejected operations must leave the accepted log replayable; add this exact regression and interruption tests.

2. **P1 — `fsck` can certify corrupted evidence and divergent state.** At `project.py:2521`, objects are checked for existence, not whether their bytes match the recorded content hash. At `project.py:2554`, projection comparison checks row counts rather than values and omits the newer research/review tables. HEAD and parent-chain consistency are not checked. Independently changing a document object's bytes, changing a code description directly in a disposable SQLite copy, or setting a fixture HEAD to zero all still produced `status: ok`. Hash every referenced object, validate sequence/HEAD/parent consistency and referential invariants, and compare deterministic contents of every projection table. Bundle validation depends on this checker, so this is central to the product's promise.

3. **P1 — Feedback classification validates evidence against text supplied by Results.** In `src/bewley/commands/insights.py:705`, the Jobs denominator supplies document IDs only. At line 713, quote validation uses `scenario["response_text"]` from Results; the supplied revision is copied into the output without matching it to Jobs. A synthetic result retaining a valid document ID and codebook fingerprint, but replacing the revision with `wrong-revision` and the text with a sentence absent from the corpus, was accepted with no warning. Validate the full scenario identity, revision, source digest, and frozen codebook against the originating package; resolve evidence against its immutable source. Apply a shared validator across all ingest commands, including the focused-framework path, which currently checks row count without matching the returned scenario to the originating one.

4. **P1 — Project bundles omit newer workflow evidence.** `src/bewley/bundle.py:21` and line 81 recognize six exact evidence filenames plus `.ep` names containing jobs/models/results. They omit default focused-framework JSON, focused-mapping CSV, focused ingest/apply sidecars, feedback codebook/classifications/aggregate, feedback `ingest-log.jsonl`, `models.json`, and survey-import manifests outside `.bewley`. A packaging probe confirmed omission of files using these default names. Restoring core codes does not restore the complete analysis or review record. Register run artifacts by role, digest, and relationship in a durable manifest; have pack/unpack preserve that manifest's closure. Test a complete focused and feedback workflow through pack/unpack.

5. **P2 — Open-coding ingest accepts unexpected scenarios.** `src/bewley/commands/open_coding.py:471` checks missing expected pairs but does not reject pairs outside the Jobs denominator. A one-document pilot Jobs package accepted two document results and reported `expected_answers: 1`, `result_count: 2`, and `partial: false`. This makes accidental mixing of full and pilot results look valid. Compare expected and observed identities in both directions. Derive expected models from registered execution metadata rather than only those that happened to return results.

6. **P2 — An unreviewed queue is automatically accepted, and the sidecar is not the promised full proposal record.** `open_coding.py:775` switches to review-by-deletion whenever none of the current candidates has a decision. A new queue with two proposals created two annotations, exited zero, and only emitted a warning. This is intentional compatibility behavior, covered by an existing test, but an unsafe default for an interface described as reviewed coding. Make legacy acceptance an explicit opt-in with a documented migration. Separately, `open_coding.py:508` logs only candidate ID, code name, document path, and resolution status: no quote, definition, revision, offsets, or per-candidate model attribution. Preserved Results retain some source evidence, but the sidecar alone does not preserve the full proposal as AGENTS.md promises. Store the complete candidate record and its lineage.

7. **P2 — Code merges can create cycles.** `project.py:2306` accepts `alpha → beta` followed by `beta → alpha`. Both commands and subsequent `fsck` succeed. The resolution helper stops traversing when it sees a cycle instead of reporting corruption, leaving no active terminal target. Resolve the target to its surviving active code and reject cycles before appending. Add merge-family and integrity regression coverage.

8. **P2 — Next-action metadata and method selection are unreliable.** `src/bewley/commands/common.py:103` defaults legacy action dictionaries to `mutates_state=False`. In a freshly initialized project, `bewley next` recommends `study set` with that false flag and unresolved placeholders. A project explicitly configured for thematic analysis still receives grounded-theory documentation and a core-category checklist. Artifact discovery in `commands/agent.py` also relies on a few fixed filenames and code counts, rather than registered runs and unresolved decisions. Build typed actions once, distinguish templates from executable actions, and derive guidance from declared method and actual review/run state.

**Recommended sequence.**

1. Ship an integrity release: replay-safe rejection, stronger fsck, trusted-source ingest, complete bundle evidence, explicit review mode, and the regressions above. Preserve existing events and stable error/envelope contracts; specify migration where behavior changes.
2. Add automated PR verification. The only tracked GitHub workflow deploys Pages; it does not run the Python checks. Run compileall, pytest, contract sync, and package-install checks in CI. Pin or constrain the EDSL VCS dependency to a tested revision/range instead of an unpinned default branch. Add fault, stale-result, wrong-run, malformed-artifact, and interrupted-write tests: 247 passing tests currently miss these failure classes.
3. Finish the research model's practical payoff: general released-codebook coding through jobs → ingest → review → apply; case/attribute/speaker query filters and code × case matrices with explicit denominators. The feedback classifier already demonstrates fixed-codebook classification, but it is not a general released-codebook annotation workflow.
4. Implement the narrow corpus-lineage slice from #11. Keep metadata out of analysis text, preserve raw inputs and transformations, and expose lineage in quote exports and bundles. Establish the migration seam before considering #10.
5. Reduce duplication as these fixes land. `cli.py` is appropriately thin, but `project.py` is 3,597 lines, `html_export.py` 2,139, and `commands/insights.py` 1,208. Extract persistence/replay, media, and shared run validation into owning library modules. Expand dense one-line insight handlers and share action/artifact contracts. Avoid a wholesale refactor before the behavioral regression coverage exists.

REFI-QDA interchange and a lightweight review-file round trip remain sensible later work. Neither a full desktop UI nor multi-agent corpus generalization is required to make the existing product substantially more dependable.
